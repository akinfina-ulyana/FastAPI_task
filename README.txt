Тестовое задание: Улучшение API-сервиса для обработки транзакций
Описание:
Необходимо провести оптимизацию и рефакторинг API-сервиса, предназначенного для обработки транзакций пользователей. Сервис сталкивается с проблемами производительности, сбоями при обработке данных, ошибками в коде и логике, что требует улучшений для повышения его надежности и устойчивости. Важной частью задания является приведение кода в более структурированный вид, оптимизация и устранение возможных излишне сложных решений.
Цели задания:
Улучшение производительности:
Оптимизировать работу сервиса с учетом большого объема данных и множества пользователей.
Ускорить обработку транзакций, уменьшить время отклика и повысить стабильность.
Повышение надежности и консистентности данных:
Внедрить механизмы предотвращения ошибок и сбоев при обработке данных.
Рефакторинг кода:
Улучшить читаемость, структуру и поддерживаемость кода, придерживаясь принципов SOLID.
Устранить избыточные или сложные решения.
Добавить аннотации типов.


Организация создания отчетов:
Вынести генерацию отчетов в отдельный бэкраунд-воркер (используя Celery, Dramatiq или аналогичный инструмент).
Логика работы сервиса:
Регистрация пользователей:
При регистрации нового пользователя автоматически создаются кошельки по всем доступным валютам.
Изначально кошельки пустые, и баланс пользователя равен нулю.
Регистрация возможна только по уникальному email.
реализовать jwt авторизацию
Пополнение и снятие средств:
Пользователь может пополнять счета и проводить транзакции на снятие средств.
Баланс не может быть отрицательным.
Роллбэк/отмена транзакций:
В случае отмены транзакции для снятия средств деньги возвращаются, а для пополнения списываются с баланса.
Заморозка аккаунта:
При заморозке аккаунта все операции (включая откаты) запрещены.
После разблокировки операции возобновляются.
Создание отчетов:
Генерация отчетов за последние 52 недели. Показатели:
Начало и конец недели.
Количество новых пользователей за неделю.
Количество пользователей, сделавших хотя бы один депозит (включая отмененные).
Сумма всех пополнений (без отмененных).
Сумма всех снятий (без отмененных).
Общее количество транзакций (включая отмененные).
Количество транзакций без отмен.
Дополнительные требования:
Архитектура:
Соблюдать принципы SOLID и чистого кода.
Код должен содержать аннотации типов (typing).
Фоновые задачи:
Создание отчетов вынести в отдельный бэкграунд-воркер (например, Celery или Dramatiq).
Инструменты проверки качества:
Настроить pre-commit хуки для:
mypy (проверка типов);
flake8 (анализ кода на соответствие PEP8);
isort (сортировка импортов).
Контейнеризация:
Настроить Docker / Docker-compose окружение.
Перейти на PostgreSQL вместо SQLite.
Тестирование:
Покрыть код unit и integration-тестами с использованием pytest.
Документация:
Добавить пошаговую инструкцию для запуска проекта:
Установка зависимостей.
Команда для миграции базы данных.
Команда для заполнения базы тестовыми данными.
Приложить коллекцию Postman для демонстрации функционала.
